# Nexus Audit - Project Roadmap & Implementation Plan

This document serves as the persistent memory and execution guide for the Nexus Audit tool. It outlines the completed work, the current phase, and future architecture goals. **Any AI agent picking up this project should read this document to understand the current context and next steps.**

## The Vision
Transition the Nexus Audit script from a "run-once-and-exit" utility that relies heavily on AI into a **modular, persistent application** with offline capabilities and interactive web-based controls. The tool should not copy codebases, but audit them directly.

---

## Phase 1: Config Health Baseline [✅ COMPLETED]
**Goal**: Integrate the Configuration Health audit directly into the main dashboard and visual architecture graph.
**Status**: Committed and verified.
**Implementation details**:
- A dedicated `Config Health` parser was added to audit the project kernel (e.g., `settings.py`).
- The dashboard UI was updated to remove the separate Config tab and instead inject a prominent full-width "Project Kernel" banner above all other apps.
- A "CONFIG" node (orange hexagon) is dynamically injected into the `vis-network` architecture graph and sidebar.

---

## Phase 2: Enhanced UI & Offline Upgrades [✅ IMPLEMENTED — AWAITING USER VERIFICATION]
**Goal**: Make the dashboard smarter and less dependent on the AI API by injecting native upgrade commands and making the config health UI interactive.

### Step 2.1: Offline Dependency Commands
- **Context**: Currently, checking PyPI for outdated packages happens natively, but the actual `pip install --upgrade ...` commands are only generated by the AI backend.
- **Task**: Modify `nexus_audit/dependency.py` (`_scan_pkg`). Since we already fetch the `latest` version from PyPI, dynamically construct the upgrade command (`pip install package==latest`) directly in Python.
- **UI Integration**: Update `html_report.py` to render this upgrade command directly next to outdated packages in the dashboard, ensuring upgrade paths are always available even when offline or out of API quota.

### Step 2.2: Interactive Config Health
- **Context**: The Config Health banner currently just lists errors.
- **Task**: Convert these failure rows into interactive `<details>` accordions.
- **UI Integration**: Clicking an error should expand to show:
  1. The specific file (e.g., `settings.py`).
  2. Hardcoded logic/explanations for common failures (e.g., explaining *why* `DEBUG=True` is dangerous).
  3. Actionable steps to fix the issue.

---

## Phase 3: Modular Server Architecture [✅ IMPLEMENTED — AWAITING USER VERIFICATION]
**Goal**: Convert the tool into a persistent application with granular controls via the web dashboard.

### Step 3.1: Granular CLI Toggles
- **Task**: Update `main.py` to accept arguments to disable specific scans (e.g., `--skip-deps`, `--skip-ai`, `--only-app nexus_economy`).

### Step 3.2: Persistent Web Dashboard
- **Task**: Upgrade the `--serve` functionality. Instead of just serving a static HTML file, it should act as a lightweight local server.
- **UI Integration**: Add a control panel to the top of the HTML dashboard with toggle switches for each scanner (Dependencies, Complexity, Security).
- **Execution**: Add a "Run Audit" button to the UI that hits a local API endpoint (e.g., `POST /run_audit`) and runs `main.py` dynamically based on the toggles selected in the UI.
